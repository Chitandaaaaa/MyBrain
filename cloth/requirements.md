# 服装归档与学习网站 — 需求文档（v0.1）

> 本文档为后续沟通与开发的**基准**。所有对话中出现的服装品类名称，均以第 6 节《专业名词表》为准，禁止自造或混用俗称。

---

## 1. 项目背景

用户日常对服装品类的认知较薄弱，通常只能说出"外套、衬衫、毛衣"等泛称；遇到"呢子大衣、夹克、工装裤"等细分品类时，往往**叫不出准确名称、也不清楚其特征**。

目标：构建一个网站，将市面上常见的服装按**层级分类归档**，支持随时查阅与系统学习，相当于一个"服装品类知识库"。

---

## 2. 目标用户

- 服装品类认知薄弱、希望系统学习的普通用户（本期主角）
- 未来可扩展为团队 / 公众共享的服装知识库

---

## 3. 范围（Scope）

**包含（本期范围）：** 上装、外套、下装、裙装、内衣、袜类 —— 即用户所说的"除鞋以外的所有衣物"（含袜子、裤子、内裤、上衣等）。

**排除（明确不在本期）：** 鞋类（运动鞋、皮鞋、靴子等）；箱包配饰（帽、包、腰带等，可作为后续独立模块）。

---

## 4. 功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-1 | 分类浏览 | 按「大类 → 子类」两级层级浏览（数据结构预留三级扩展能力） |
| FR-2 | 子类详情 | 每个子类展示：中文名 / 英文名 / 定义 / 核心特点 / 常见面料 / 搭配建议 |
| FR-3 | 检索 | 支持按名称关键词搜索（demo 阶段用前端过滤即可） |
| FR-4 | 数据可扩展 | 分类数据以结构化方式（如 JSON / JS 对象）维护，便于后续增删改 |
| FR-5 | 学习导向 | 界面弱化电商属性，强调"知识呈现"而非"商品售卖" |
| FR-6 | 分面筛选 | 在主分类树之外，支持按「面料 / 长度 / 风格 / 季节」等横切维度组合筛选（维度内多选 OR，维度间 AND） |
| FR-7 | 自然语言匹配 | 用户输入口语/模糊描述，系统返回对应的 1 种或多种服装品类（由 AI 分析，结果须限定在第 6 节名词表内） |

### 6.3 横切属性维度（Facet · 跨品类贯穿，统一叫法）

> 这些维度不是独立分类，而是附着在「子类」上的标签，用于组合筛选。

| 中文术语 | 英文 | 取值（受控词表） | 说明 |
|----------|------|------------------|------|
| 面料 | Fabric | 棉、麻、羊毛呢、丹宁、羽绒、皮革、针织、尼龙、雪纺、蕾丝 | 衣物材质 |
| 长度 | Length | 短款、常规、长款、超长款 | 衣/裤下摆位置（受控 4 档，避免无限细分） |
| 风格 | Style | 休闲、正式、街头、英伦、运动、优雅、通勤、贴身 | 整体调性 |
| 季节 | Season | 春、夏、秋、冬、四季 | 适用季节 |
| 版型 | Fit / Silhouette | 宽松、修身、直筒… | 轮廓与松紧（预留，详情字段） |
| 领型 | Collar | 圆领、翻领、立领… | 领口样式（预留，详情字段） |
| 袖型 | Sleeve | 长袖、短袖、无袖… | 袖子样式（预留，详情字段） |

### 6.4 分类策略（核心约定 · 防歧义）

服装分类是**多维度**的，单一树状分类会产生歧义。本项目采用**「主分类树 + 横切属性」双层模型**：

- **主分类树（大类 → 子类）**：回答"这是什么衣服"，是品类的**身份**。例：大衣、夹克、T恤。
- **横切属性（面料/长度/风格/季节）**：回答"它长什么样、什么材质、什么场合"，可跨品类组合。

**关键示例（统一以此为准）：**
- `呢子大衣` = 子类【大衣】 + 面料【羊毛呢】，**不是**与"大衣"平级的新类。
- `皮夹克` = 子类【夹克】 + 面料【皮革】；`羽绒服` = 子类【外套类】 + 面料【羽绒】。
- `下摆盖住大腿的长款衣物` = 任意子类 + 长度【长款/超长款】。长款大衣与长款连衣裙品类不同，靠"品类+长度"精确区分。
- 因此：**新增一个细分品类前，先判断它是"新品类"还是" existing 品类 + 新属性值"**；优先用属性表达差异，避免分类树无限膨胀。

### 6.4 通用流程术语

| 中文术语 | 说明 |
|----------|------|
| 归档 | 将某服装品类按分类体系录入系统的动作 |
| 检索 | 按关键词/筛选条件查找已归档品类 |
| 子类 | 大类下的细分品类（见 6.2） |
| 层级 | 分类的树级深度（本期两级，预留三级） |

## 9. Demo 交付说明

- 前端：`index.html`（从 `data/categories.json` 加载数据，单一数据源，前后端共用）
- 运行：因 fetch 加载 JSON，需经本地服务器打开，例如 `python3 -m http.server 8000` 后访问 `http://localhost:8000`
- 交互：左侧品类树导航 + 上方分面筛选（面料/长度/风格/季节，可组合）+ 右侧子类卡片（点击展开详情含属性标签）+ 顶部关键词检索
- 已落地双层分类模型：每个子类带 fabric/length/style/season 属性，可演示"外套 + 羊毛呢 + 长款 = 呢子大衣"

## 10. AI 自然语言匹配（已搭骨架，待接入 key）

目标：用户用口语/模糊描述一件衣服（如"到膝盖下面毛茸茸的长外套"），系统返回对应的 1 种或多种服装品类。

- **配置位置**：`config/ai-config.json` —— API 底座、模型、key 环境变量名、system prompt 均在此；改配置即可换模型/服务商，无需动代码。
- **匹配模块**：`ai-match.mjs`（Node ESM）读配置 + `data/categories.json`，调用 OpenAI 兼容 `/v1/chat/completions`，解析为结构化结果；**未配 key 时自动走本地关键词兜底**，保证流程可跑通。
- **接口契约**：
  - 输入：`description`（中文自由描述字符串）
  - 输出：`[{ cat: 大类, sub: 子类, confidence: 0~1, reason: 简短中文理由 }]`（最多 topK=5，按置信度降序）
  - 约束：返回的 cat/sub 必须来自第 6 节名词表，禁止自造品类
- **快速验证（无 key 走兜底）**：`node ai-match.mjs "到膝盖下面毛茸茸的长外套"`
- **接入真实 LLM**：设置环境变量 `LLM_API_KEY` 后重跑同上命令即可（默认走 `https://api.openai.com/v1`，可在配置中改 `baseUrl` 指向任意 OpenAI 兼容服务）
